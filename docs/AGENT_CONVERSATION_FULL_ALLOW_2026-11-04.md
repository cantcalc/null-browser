# NULL 1.1.0-beta.4 — 대화 구분 및 전체 허용

2026-11-04, macOS arm64 개발/미리보기 앱. 이전 beta.3은 일반 동작만 자동 허용했고 중요한 동작은 계속 확인했습니다. 이번 변경은 사용자가 다시 요청한 전체 허용을 별도 실행 모드로 반영합니다.

## 대화 UI

- 내 메시지: 오른쪽 정렬, “나” 표시, 테마와 반대 명암의 말풍선. 줄바꿈과 입력 원문을 그대로 표시합니다.
- AI 답변: 왼쪽 정렬, 아이콘과 “NULL” 표시, 본문·목록·코드 구성을 유지합니다.
- 두 발신자를 접근성 이름으로도 구분합니다. 본문을 선택해 복사할 수 있습니다.
- 이전 메시지를 읽는 중에는 작업 진행 상황 갱신이 화면을 아래로 끌어내리지 않습니다. 새 메시지를 보내면 최신 위치를 따라갑니다.

## 전체 허용

새 기본값은 `approvalMode: auto`입니다. 기존 저장 설정에 이 항목이 없어도 새 기본값을 사용합니다. 사이드바 입력창 위의 **전체 허용** 표시와 설정의 같은 스위치로 바꿀 수 있고 재시작 후 유지됩니다.

전체 허용에서는 요청 범위의 실행 가능한 클릭·입력·양식 제출·주소 이동에 별도 승인창을 띄우지 않습니다. 중요한 라벨이나 이름 없는 버튼도 이 모드에서는 동작 승인을 건너뜁니다. 대기 중인 동작 승인이 있다면 전체 허용으로 전환할 때 이어서 처리합니다. 모델 지시문도 현재 모드를 반영합니다.

페이지가 바뀌거나 사용자가 조작하면 이전 요소는 실행하지 않고 최신 화면을 다시 읽습니다. 전체 허용에서 일반 상태 변경마다 “이어서 진행”을 요구하지 않습니다. **중요 작업 확인** 모드에서는 중요한 동작의 승인과 사용자 조작/URL 변경에 따른 일시정지를 유지합니다.

전체 허용은 도구가 원래 제공하지 않는 권한을 추가하지 않습니다. 로그인·비밀번호·결제 정보 입력·파일 업로드·민감 화면은 직접 처리하며, 사설망·임의 JavaScript/셸·파일 시스템·쿠키 접근·다른 워크스페이스 접근은 해제하지 않습니다. 이미지 전송의 미리보기 확인과 페이지 데이터 전송 동의도 별도입니다. 중지와 취소는 유지합니다.

## 검증

- TypeScript 두 검사, 빌드, macOS `.app` 패키징, navigation 회귀 검사 통과.
- 실제 Electron native 검사 28개 그룹 통과. 전체 허용에서 로컬 테스트 버튼/쓰기 양식 실행, 페이지 변경 재관찰, 사설망 차단을 확인했습니다.
- 중요 작업 확인으로 대기시킨 로컬 테스트 작업을 전체 허용으로 바꾸어 실행하고, 다음 작업도 별도 승인 없이 끝나는 것을 확인했습니다. 실제 외부 게시/전송/삭제/결제는 테스트하지 않았습니다.
- 소스 UI와 패키지 UI에서 발신자 구분·두 테마·본문 선택·읽던 스크롤 위치·권한 모드 전환/재시작을 확인했습니다. 두 실행 모두 UI/재시작 검사는 모의 API 및 모의 암호화 저장소를 사용하므로 실제 제공자나 실제 OS 암호화 재시작 성공으로 계산하지 않습니다. 패키지 UI 검사 직전의 별도 실제 OS 암호화 probe는 통과했습니다.
- UI 검사는 모의 제공자와 별도 프로필을 사용합니다. 사용자 API 키나 실제 계정 데이터를 테스트 프로필로 복사하지 않습니다.
- 테마 검사는 설정 화면에서 실제 테마를 선택·저장하고 적용을 확인하도록 고쳤습니다. 설정 저장 API만 호출하는 것은 현재 화면의 테마 변경 검증이 아닙니다.
- 창 크기는 요청값과 실제 native/renderer content 크기를 기록합니다. 이 호스트에서 1440×900 요청은 실제 1440×895로 제한되므로 900px 높이를 검증했다고 주장하지 않습니다.

macOS의 Developer ID 서명·공증은 준비되지 않아 로컬 ad-hoc 서명을 사용합니다. 패키지 검사 중 OS 암호화 연결의 첫 LaunchServices 검사에서 재시작 복원 실패가 났고, 재시도에서는 초기 OS 저장소 probe도 실패했습니다. 별도 모의 저장소 패키지 UI 검사에서는 UI/권한 동작을 통과했습니다. 실제 OS 암호화의 전체 재시작 검증은 이번 버전에서 통과로 표시하지 않습니다. 기존 beta.3에서도 관찰한 간헐 문제이며 원인을 확정하지 않았습니다. 암호화 우회·평문 저장·키체인 권한 변경은 하지 않습니다.

실제 사용자 AI 미리보기 프로필에서는 최초 연결 확인 실패 후 설정의 연결 확인 재시도로 저장된 Gemini 연결과 8개 무료 모델이 복구됐습니다. 실제 Gemini 3.5 Flash Lite로 “구글에서 NULL browser 검색해줘”를 실행해 동작 승인/재개 버튼을 누르지 않고 검색 결과·최종 답변·페이지 확인 완료를 확인했습니다. 실제 화면에서 오른쪽 내 말풍선과 왼쪽 NULL 답변, 전체 허용 표시도 확인했습니다. 이 성공이 앞선 OS 암호화 재시작 검사 실패를 해소했다는 뜻은 아닙니다.

GitHub Release, DMG/ZIP, Windows 패키지는 이번 작업에서 배포하지 않았습니다. 현재 설치된 일반 배포 앱과 기존 사용자 데이터는 유지하고, 별도 AI 미리보기 앱에 변경을 적용합니다.
