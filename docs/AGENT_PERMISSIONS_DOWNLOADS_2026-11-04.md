# NULL 1.1.0-beta.3 — 에이전트 승인 및 다운로드 수정

> 후속 검토: 이 문서의 승인 정책은 beta.3 당시 기준입니다. 최신 beta.4는 [대화 UI/전체 허용 보고서](AGENT_CONVERSATION_FULL_ALLOW_2026-11-04.md)를 따릅니다. 당시 다운로드 테마 검사는 저장 API를 호출했으나 라이브 테마 전환 자체는 확인하지 못했습니다. 파일 바이트·진행·재시작·기록 삭제 검사는 별도로 유효합니다.

2026-11-04, macOS arm64 개발/미리보기 앱. 공개 Release, DMG/ZIP, Windows 배포는 이번 작업에서 만들거나 올리지 않았습니다. 기존 설치 앱과 브라우저 데이터 식별자는 유지합니다.

## 에이전트 실행 정책

일반 공개 웹 탐색·검색·비민감 입력·메뉴/탭/펼치기 등의 클릭은 매번 승인하지 않고 실행합니다. 새 공개 URL이나 사용자가 입력한 단어와 완전히 일치하지 않는 일반 검색어도 같은 정책입니다. YouTube 영상 URL의 `v`, `list`, `pp` 같은 정상 쿼리를 중요한 작업으로 오인하던 판정을 줄였습니다. PostgreSQL/저장소 같은 단어도 전송·저장 동작으로 분류하지 않습니다.

결제·구매·게시·메시지 전송·삭제·구독·계정/권한 변경, 설치/실행 패키지 링크, 상태 변경 주소, 일반 쓰기 양식 제출은 확인합니다. 이름 없는 버튼과 의미가 불명확한 확인/계속 버튼도 확인합니다. 비밀번호·결제 필드·사설망·임의 스크립트/파일 시스템 접근을 허용하는 완전 무제한 설정은 아닙니다. 로그인/민감 화면은 사용자가 직접 처리합니다.

실제 사이트에서 버튼이 렌더링 후 바뀌면 기존 요소를 클릭하지 않고 새 요소 목록을 다시 읽도록 수정했습니다. 사용자가 직접 발생시킨 입력과 URL 변경은 별도로 검증하고 일시정지합니다. 실제 native 입력을 사용하는 회귀 검사로 이를 구분했습니다. 연결 설정에서 다시 연결한 뒤 사이드바를 열었을 때 오래된 오류 문구가 남는 문제도 수정했습니다.

## 다운로드

- 원인: 기존 다운로드 처리/저장 기록은 있었으나 툴바에 진행 표시와 직접 진입 버튼이 없었습니다.
- 주소창 옆 다운로드 버튼은 진행 개수·진행 링을 표시하고 클릭하면 기록 패널을 바로 엽니다.
- 패널은 웹페이지 옆에 공간을 확보합니다. 진행률, 완료/취소/중단 상태, 취소, 열기, Finder, 기록 삭제를 제공합니다. 전체 크기를 모를 때 임의의 완료율을 표시하지 않습니다.
- 재시작 후 기록이 있어도 메모리의 DownloadManager에는 항목이 없어 열기/Finder가 무반응이던 문제를 수정했습니다. 메인 프로세스의 저장 기록에서 경로를 찾습니다. 렌더러가 임의 경로를 전달하지 않습니다.
- 기록 삭제는 실제 파일을 삭제하지 않습니다. 진행 중 파일은 열지 않습니다. 시크릿에서 일반 다운로드 기록/파일에 접근하지 못하도록 유지합니다.
- 초기 기록을 비동기로 읽는 사이 발생한 새 진행 이벤트가 덮어써지지 않도록 병합합니다.

다운로드 검사는 128KiB 파일의 실제 바이트를 비교하고 지연 전송·취소·연결 중단, 재시작 후 기록 복원, 기록 삭제 후 재시작, 실제 파일 유지, 시크릿의 일반 기록 접근 차단을 확인합니다. 다크/화이트 × 800×600/1280×720에서 패널이 native 웹페이지를 가리지 않는 것을 확인했습니다. 열기/Finder는 테스트에서 OS 호출을 가로채 정확한 저장 경로로 연결되는지 확인했으며 Finder 자체 동작을 자동 검증했다고 주장하지 않습니다.

native 검사 중 한 번은 화면 캡처 surface를 얻지 못해 중단됐고, 같은 코드 재실행에서는 캡처를 포함한 전체 검사가 통과했습니다. 최초에 보이지 않는 창으로 보낸 키 입력은 실제 사용자 입력 검증으로 사용할 수 없어, 창을 표시하고 실제 trusted pointer 이벤트 수신을 확인하는 검사로 바꿨습니다.

## 제한

모든 웹앱의 부작용을 라벨과 양식 속성만으로 완전히 식별할 수 있다는 보장은 아닙니다. 복잡한 에이전트 작업, 모든 확장 프로그램, 모든 외부 다운로드 사이트를 검증한 상태는 아닙니다.

실제 사용자 Gemini 연결은 재실행 직후 한 번 확인 실패 문구가 나왔고 연결 확인 재시도로 8개 무료 모델과 기존 연결이 복구됐습니다. 그 최초 실패 원인은 확정하지 못했습니다. 키를 읽거나 복사하지 않았고, 실제 사용자 프로필에 디버깅 포트를 연결하지 않았습니다. 최종 앱 재실행에서는 기존 연결이 자동 복원됐습니다. 실제 Gemini 3.5 Flash Lite로 “유튜브에서 NULL browser 검색해줘”를 실행해 추가 승인 없이 `https://www.youtube.com/results?search_query=NULL+browser` 검색 결과·페이지 확인 완료·최종 답변을 확인했습니다. 이 한 흐름의 실제 API 검사와 다른 모의 API/native 검사를 구분하며 전체 사이트 성공률을 뜻하지는 않습니다.

Developer ID 서명·공증 인증 정보가 없어 로컬 ad-hoc 서명만 사용합니다. 서명 무결성 확인과 Gatekeeper 통과는 다릅니다. 기존 공개 버전/업데이트 제공 저장소는 바꾸지 않았습니다.
