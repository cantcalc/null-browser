# NULL 에이전트 동작·UI 수정

2026-11-04 · 1.1.0-beta.2 · macOS arm64

## 발견한 원인

에이전트가 WebContents.loadURL을 직접 호출해 실제 페이지는 이동했지만, TabManager의 URL은 null://newtab으로 남았습니다. 내부 페이지 가드가 URL/제목 상태 알림과 native view 표시를 막아 주소창·화면은 계속 새 탭으로 표시됐습니다. 또 작업 탭을 배경으로 생성했고, 실제 도구 성공 근거 없이 모델의 문장만으로 완료 상태를 만들 수 있었습니다. 이전 QA는 URL 이동과 native 표시는 따로 검사해 React까지 이어지는 이 결함을 놓쳤습니다.

## 수정

- AI 이동도 기존 TabManager의 navigateTab을 거쳐 URL/제목/로딩/오류/레이아웃을 일치시킵니다. 별도 구조로 브라우저를 재작성하지 않았습니다.
- 새 작업 탭은 생성 즉시 선택합니다. 실제로 확인한 페이지를 결과에 표시합니다.
- 첫 단계에 공식 API의 도구 호출 모드를 사용합니다. 빈 페이지·거부·오류·도구 없는 잡담은 실행 성공 근거가 아닙니다.
- 실제 관찰한 웹페이지가 있어야 완료합니다. 간단한 명시적 사이트 열기 요청은 목적지 호스트/경로도 비교합니다. 복잡한 모든 작업의 의미적 성공을 보장하지는 않습니다.
- 도구 실행 중의 중간 잡담과 검증 전 성공 주장은 사용자 답변에 표시하지 않습니다. 결과 확인 후 최종 답변을 보여줍니다.
- 중지는 스트림 취소 및 정리를 기다리고, 중요한 클릭·입력 승인과 수동 로그인은 유지합니다.

## 간편 UI

- 사이드바는 에이전트 전용입니다. 일반 채팅/에이전트 체크박스와 중복 제공자/모델 선택, 원시 모델 ID와 반복 작업 카드를 제거했습니다.
- 헤더, 작업/결과 영역, 하단 입력창과 모델 선택만 기본 노출합니다. 참조/캡처는 +, 작업 단계는 접힌 상세 내역으로 옮겼습니다.
- 설정은 한 제공자의 API 연결·도구 지원 모델·기능/전송 동의 위주로 줄였습니다. 위치·새 탭 작업·참조·한도 전환은 추가 설정에 접었습니다.
- 재실행 후 패널을 열면 저장한 연결의 모델을 확인합니다. AI를 쓰지 않을 때 API를 호출하거나 모든 탭을 로딩하지 않습니다.
- [Aside 공식 화면](https://aside.com/)과 [에이전트 설명](https://aside.com/features/browser-agent)의 입력 중심·작업 중심 구성을 참고했습니다. Aside의 전체 성능·호환성·기능과 동등하다는 뜻은 아닙니다.

## 검증

- Native AI 22개 그룹 통과: 실제 암호화, 격리, 승인/취소, navigation, 무근거 완료 거부 등.
- 소스 UI: 좌/우 × 800×600 / 1280×720 / 1440×900 6개 배치, 단일 모델 선택·간편 설정·시크릿 차단·재시작 복원 통과.
- 모의 provider + 실제 공개 example.com 이동에서 주소창·탭 제목·선택 상태·native view 표시와 결과 링크를 함께 확인했습니다. 도구 없는 성공 주장이 UI에 나타나지 않는지도 검사했습니다.
- 기존 20탭 lifecycle 및 경량화 12개 시나리오 통과.
- 맥 패키지: 같은 6개 배치·실제 OS 암호화·재시작·foreground 페이지 표시·무근거 완료 거부 통과. provider 응답은 이 자동 검사에서만 모의했습니다.
- **실제 Gemini 3.5 Flash Lite 연결 + 실제 앱 UI:** 저장된 연결을 복원한 뒤 “유튜브 켜줘”를 전송했습니다. native YouTube 페이지가 표시되고, 주소창이 www.youtube.com, 탭 제목이 YouTube로 바뀐 뒤 “유튜브를 켰습니다.”와 페이지 확인 완료/결과 페이지 버튼이 나타나는 것을 확인했습니다. 사용자 키 값을 읽거나 복사하지 않았고 실제 프로필에 inspector나 mock을 넣지 않았습니다.
- TypeScript, Electron typecheck, build, navigation 검사 통과. 맥 ASAR의 현재 빌드 파일 14개 해시 일치·QA 파일 제외·서명 무결성 검사 통과.

## 남은 제약

- 이 실사용 검증은 Gemini의 사이트 열기 한 흐름입니다. 실제 무료 한도 전환, Groq/OpenRouter 유효 키 응답, 이미지 이해, 복잡한 여러 사이트 작업 전체를 검증한 것은 아닙니다.
- 패키지 자동 QA 첫 실행에서 재시작 연결 확인 assertion이 한 번 실패했습니다. 당시 세부 오류를 구분할 자료가 부족하며, 동일 빌드 재검사 및 실제 저장된 Gemini 연결 복원은 통과했습니다. 재발 여부를 확인해야 하는 미확정 항목으로 남깁니다.
- Developer ID 서명/공증은 없고 로컬 ad-hoc 서명입니다. 키체인 접근은 실행 환경·서명에 따라 달라질 수 있으며 평문 저장·ACL 변경으로 우회하지 않았습니다.

## 배포 범위

Mac 로컬 개발판입니다. 설치된 일상용 1.0.1 앱 및 기존 데이터 저장 경로/암호화 식별자를 유지합니다. Windows·DMG·새 공개 Release는 이번 작업에서 만들지 않습니다. 새 UI에서 기존 API 키를 다시 입력하도록 요구하거나 키를 복사하지 않습니다.
